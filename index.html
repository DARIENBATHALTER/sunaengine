Every physics engine drifts.
This one cannot.

SunaEngine is an open-source particle physics engine that guarantees bit-identical simulation output — every time, everywhere, on any WebGPU-capable device. Not "close enough to look the same": the same 256-bit state hash, on your laptop and on a stranger's GPU.

No mainstream engine can promise that, because floating-point rounds differently across GPUs and drivers, and chaos amplifies the last bit into a different world. SunaEngine's solver contains no floating point at all — integer fixed-point throughout — which is what makes the guarantee possible. This page does not ask you to take any of it on faith: the 64 hex digits under each simulation are a live digest of the entire particle state, recomputed as it runs.

Two independent simulations, booted from the same scene, fed the same injection schedule. They never communicate and are never corrected toward each other; they simply compute the same thing. Water pours in from the left, swirls, and settles — every particle drawn as a plain disc, deliberately cheap on your GPU, so what you compare is the motion itself: two pours landing, piling and sloshing in perfect unison. And they are not hands-off: move your cursor through either pane and you stir the water — the same gesture is fed to both simulations as one substep-indexed schedule, so even your hand cannot tell them apart.

Figure 2 — Smooth Rewind

Particle fluids cannot be rewound. Chaos amplifies the last bit of every velocity, so no floating-point engine can take a splash backwards and land on the world it actually came from — the errors compound in reverse, too. A bit-exact engine has no such debt. Here, memory is not video: the moment you touch this pool — stir it with your cursor, drop water, hold the button — it starts recording a .sunar journal: the exact starting state plus your inputs, indexed by substep. No frames are stored.

When your cursor leaves the window, the pool replays your session from the journal alone and compares the replay's final digest, byte for byte, against the run you actually performed. Then the scrubber appears: drag your splash smoothly backwards and forwards through time. Reverse is replay-from-nearest-keyframe-forward — snapshots every 24 substeps make it feel continuous — and every landing is the exact state, not an approximation of it.

What a bit-exact engine is for

Determinism is not a benchmark number — it is a different set of things you are allowed to build:

Multiplayer without state sync. When every machine computes identical bits, peers exchange inputs instead of world snapshots — a physics world's worth of state in a few bytes per frame, with divergence impossible rather than corrected-for.

Replays that are proofs. A recorded session is a starting state plus an input journal, a few kilobytes. Its final hash can be re-derived by anyone, so a leaderboard entry or a challenge run is verifiable — there is nothing to edit that the hash will not catch. Figure 2's byte-identity check is this property, live.

Smooth rewind. Chaos makes particle fluids irreversible in floating point; with exact state and an input journal, time is just an index — scrub it in either direction.

Reproducible simulation. A published result can be cited as (scene, inputs, hash) and re-derived exactly on any device — the difference between "our simulation showed" and "run it yourself." The same property makes CI trivial: the hash is a regression oracle that fails loudly on a single changed bit.

Training data for world models. Physics rollouts that are perfectly labeled and perfectly repeatable: a corpus regenerates bit-for-bit from seeds and schedules instead of being stored, and an evaluation suite pins its ground truth to hashes instead of tolerances.

Beyond 2D. SunaEngine simulates in 2D today, but the load-bearing techniques — fixed-point PBF, round-half-to-even force antisymmetry, order-independent integer accumulation — are dimension-agnostic, and the spec documents them for reuse.

How

Fixed point, not floating point

All simulation state is signed 32-bit fixed point — positions and velocities in Q16.16, where the integer 65 536 is one world unit. Every multiply is an exact 32×32→64-bit product followed by an arithmetic shift with round-half-to-even; overflow saturates instead of wrapping. RNE is symmetric — RNE(−x) = −RNE(x) — which is what makes pair forces exactly antisymmetric, so momentum bookkeeping cannot leak parity errors. The solver's WGSL contains no float scalars, vectors, or bitcasts; a gate greps for the tokens.

Determinism on a parallel GPU

Bit-exact arithmetic is not enough — thousands of GPU threads finish in no particular order. So every accumulation in the solver is a per-term-clamped 32-bit integer sum, which is commutative and associative: dispatch order cannot change the result. The one genuinely order-sensitive step — truncating a neighbor list that overflows its cap — is canonicalized before truncation. The engine runs a position-based fluid solve (density constraints, XSPH viscosity, surface tension) entirely under those rules.

The digest

The number under each panel is a 256-bit digest of every word of particle state: MurmurHash3 run as salted lanes over each particle, combined across particles by 32-bit addition — again commutative, so the GPU can hash in any order and still agree with the CPU reference. Half the lanes are permutation-invariant; the other half bind each particle to its storage slot, so a reordering and a physics divergence are distinguishable. A per-substep hash chain (the same construction, folded every substep) is what the repo's gates compare across machines.

Quick start

No build step, no dependencies. The engine is plain ES modules over WebGPU:

git clone https://github.com/DARIENBATHALTER/sunaengine.git
cd sunaengine
python3 -m http.server 8080
# open http://localhost:8080 in Chrome 113+
// water-only harness over the full engine (src/demo_boot.js)
import { bootWaterDemo, makeDroplet, wu } from './src/demo_boot.js';

const sim = await bootWaterDemo({ scene: 'pool' });
sim.injectWater({ substep: 60, particles: makeDroplet(wu(64), wu(10)) });
sim.step(240);
console.log(await sim.digest());
// → the same 64 hex characters on every machine

The determinism claims on this page are enforced by the repo's own gates — test/extraction_gate.html runs the frozen dam-break scene and the record→replay byte-identity check in your browser, and test/extraction_gate.md documents the cross-repo proof that this engine is byte-for-byte the SunaBox engine.
